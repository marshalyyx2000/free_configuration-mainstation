# 免配置主站「不能订阅、不能召唤」诊断与修复记录

- 时间：2026-11-09 01:40–03:05
- 子站：192.168.0.10（Ubuntu 16.04 / RK3568，Java 8，router 原生 ARM）
- 主站：Windows `SimMasterQt` + `mms_master_cli.exe`
- 现场：子站与 159 台装置中的 41 台通信正常（其余 118 台未投运）

## 1. 现象

主站连接子站 102 后：

- `dsCommState` 有时读不到；
- 对装置 RCB 执行 `enable_rcb` 超时/报错；
- 总召（GI）无报告或报告值为 `error 11`；
- 子站 `iec61850router` 进程长期 99%–100% CPU，但 102 端口仍在 listen，表现为“能连上、不响应”。

## 2. 根因

### 2.1 直接原因：RCB 实例被放大 12–18 倍，router 启动/扫描被拖死

- 现场 `station.SMCD` 中 2,250 个 `ReportControl` 的 `RptEnabled max` 为 16/12/18。
- `convert2CID` + `genconfig` 为每个 RCB 生成 max 个实例，`supervision.cfg` 达 **31,312 条 `RC(...)`**。
- router 启动时 `Reporting_createMmsBufferedRCBs()` 用 `LinkedList_add` 逐条插入，退化为 O(N²)：
  - 启动 5 分钟以上仍不 listen；
  - 主线程在 `Reporting_sendReports()` 中每 10ms 扫描全部 RCB，CPU 100%；
  - 所有 MMS 读/写/总召排队，主站表现为超时。

**证据**：`gdb -p <pid>` 主线程栈为
`Reporting_createMmsBufferedRCBs -> LinkedList_add`（启动期），
以及 `Reporting_sendReports -> IsoServer_processIncomingMessages`（运行期）；
`grep -c '^RC(' supervision.cfg` = 31312；
`grep -o '<RptEnabled[^>]*>' station.SMCD` = `max=16/12/18` 共 2250 条。

### 2.2 次生原因：加速 genconfig.jar 与现场 Java 8 不兼容

现场 `java -version` = OpenJDK 1.8.0_292；`/home/admin/router/bin/genconfig.jar`（FastGenconfigMain）由 JDK 19 编译，`CfgLphdAugmentor` 使用 Java 11 的 `Files.readString/Files.writeString`，在 Java 8 上抛：

```
java.lang.NoSuchMethodError: java.nio.file.Files.readString(...)
```

只要 SMCD 变化触发重新生成，router 就报 `Could not generate server configuration file` 并退出，MaintainServer 反复拉起失败。

### 2.3 次生原因：快速裁剪把 SubStation 的 LDevice 名写死成 `LD0`

`SclGenconfigSlice.sliceBloatedSubstation()` 重建 SubStation IED 时硬编码 `inst="LD0"`，导致 MMS 域名为 `LD0`，而主站/技术方案使用 `SubStationLD0/LLN0$dsCommState`，总召直接 `OBJECT_DOES_NOT_EXIST`。

### 2.4 次生原因：LPHD1 重复

快速裁剪只保留 LPHD + LN0 后，`CfgLphdAugmentor` 又按“开头 400 字符没有 LN(LPHD1)”补一个最小 LPHD；真实 LPHD 常在 LLN0 之后，于是同一 LD 出现两个 `LN(LPHD1)`，router 加载模型报错。

## 3. 已实施修复

### 3.1 子站模型（立即生效）

1. 现场 `station.SMCD` 将所有 `<RptEnabled max="..."/>` 收敛为 `max="1"`（保留备份 `station.SMCD.bak_max16`）。
2. 修正并重新编译 `genconfig-fast.jar`：
   - `CfgLphdAugmentor` 改用 Java 8 API（`Files.readAllBytes/Files.write`）；
   - 构建脚本改为 `javac --release 8`；
   - `SclGenconfigSlice` 的 SubStation LDevice 改为 `SubStationLD0`；
   - `CfgLphdAugmentor` 在整个 LD 块内检查 `LN(LPHD1)`，避免重复；
   - `CollapsedLDevicePruner` 保留 LPHD + LN0 数据集/RCB（轻量模型，启动快）。
3. 部署 jar 并重新生成 `supervision.cfg`：
   - **2,152 条 RC / 404 个 LD / 7.5 MB**（原 31,312 RC / 9.8 MB）；
   - `LD(SubStationLD0)` 存在，`dsCommState` 可读；
   - 首次生成约 90 s，router 启动约 100 s 后 listen 102。

### 3.2 生成器源码（防止下次下装回退）

- `master_sim/build_config.py`：`_sanitize_scl_for_genconfig()` 增加 `RptEnabled max=1` 正则收敛。
- `sim_master_qt/src/ops/config_generator.cpp`：新增 `clampRptEnabledMax()`，生成 station.SMCD 时同样收敛。
- `master_sim/tools/build_fast_genconfig.ps1`：`--release 8`。
- 本机 `%LOCALAPPDATA%\SimMasterQt\out\station.SMCD` 与 `station.zip` 已同步收敛为 `max=1`，旧安装包再次下装也不会带回 31k RC。

### 3.3 主站源码（待重新编译）

- `mms_master_widget.cpp`：自动恢复订阅时跳过 `m_commState == false` 的离线装置，避免对 118 台未投运装置逐台等 12 s 超时。
- 注意：本机 Qt 6.7.3 已不在 `C:\Qt`，本次未能重新编译/覆盖安装包；改动已提交到源码，恢复 Qt 后执行 `build_sim_master.ps1` 即可。

### 3.4 router 空值日志（源码已改，二进制未重建）

- `server_controller.cpp::updateReport()` 将“每个空 FCDA 一条 ERROR”改为计数后一条 DEBUG，避免持数据模型锁逐条写盘。
- 装置 `build.sh` 因 log4cplus 2.1.1 使用 CMake 3.12 的 `add_compile_definitions`、现场 CMake 过旧而失败，未生成带此修复的新二进制；当前运行二进制为原可用版本，功能不受影响。

## 5. 仍存在的限制

1. **非 LN0 点的报告值为 `error 11`**：轻量代理模型只保留 LPHD + LN0，`DevAlmGGIO1` 等 LN 未展开，服务端报告 `fcda->value == NULL`。数据集读会走代理读到真值；报告值仍为空。
   - 可选方案 A：把 `dsAlarm/dsWarning/dsRelayDin` 引用的 LN 一并展开（模型约 16–30 MB，启动 2–3 分钟）；
   - 可选方案 B：在 router 侧把报告源值物化到数据集条目并刷新 RCB 引用（需改 libiec61850 并重建）；
   - 可选方案 C：主站收到 `error 11` 时回读对应数据集（客户端兜底，需改 CLI/GUI）。
2. **118/159 台装置离线**：主站全站订阅会对离线装置报错。源码已加“自动订阅跳过离线装置”，但需重新编译 Qt 主站才生效；当前安装版仍会逐台尝试。
3. **router 二进制未包含空值日志优化**：装置 CMake 过旧，log4cplus 配置失败；如需彻底降低 CPU，需要先升级 CMake 或改用预编译 log4cplus。
